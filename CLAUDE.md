## Project overview

Jaaz is an Electron desktop app — an open-source AI-powered creative canvas. It combines a React frontend, a Python (FastAPI) backend, and an Electron shell. The app supports AI image/video generation, an infinite canvas for visual storyboarding, and a chat-driven agent system.

## Development commands

### Frontend (React)

```bash
cd react
npm install --force          # install dependencies (--force needed)
npm run dev                  # start Vite dev server on port 5174
npm run build                # production build (tsc + vite)
npm run lint                 # ESLint
```

### Backend (Python)

```bash
cd server
pip install -r requirements.txt
python main.py               # starts on port 57988; pass --port to override
```

### Electron (desktop shell)

```bash
# From repo root:
npm run dev                  # concurrently runs React dev + Electron
npm run dev:react            # React dev server only
npm run dev:electron         # Electron only (expects React already built/serving)
npm start                    # builds React then launches Electron

# Build desktop installers:
npm run build:mac
npm run build:win
npm run build:linux
```

### Test

```bash
npm test                     # vitest (watch mode)
npm run test:run             # vitest single run
```

Tests are in `electron/test/` and use vitest with `pool: 'forks'` (single fork). They target the Electron main-process code, not the React UI.

## Key architectural patterns

### Electron ↔ Python backend

On launch, `electron/main.js` spawns `python main.py` as a child process on a dynamically chosen port (starting at 57988). The React app communicates with the Python backend via HTTP REST + Socket.IO. In dev mode, Vite proxies `/api` and `/ws` to `127.0.0.1:57988`.

### Frontend ↔ Backend communication

- **REST**: React `api/` modules call backend REST endpoints under `/api/`
- **WebSocket**: Socket.IO is used for real-time streaming of AI agent responses (chat, magic generation). The Socket.IO server is created in `server/services/websocket_state.py` and mounted as ASGI middleware in `main.py`.
- **Electron IPC**: For OS-level operations (file pickers, browser URLs, ComfyUI management), the React app calls `window.electronAPI.*` methods exposed via `preload.js`.

### AI agent system

The AI agent pipeline uses **LangGraph** for orchestration. Chat requests hit `/api/chat` → `chat_service` → `langgraph_service/agent_service` which runs a LangGraph graph. Tools available to agents are registered in `tool_service.py` (`TOOL_MAPPING` dict) — each tool has a `display_name`, `type` (image/video/text), and associated LangChain `BaseTool`.

### Configuration

Provider/model configuration is stored as TOML in `server/user_data/config.toml` (managed by `config_service.py`). Default providers: `jaaz` (cloud API), `openai`, `ollama`, `comfyui`. The config schema: providers → models → type (text/image/video).

### Canvas system

The canvas (`/canvas/$id`) is the core feature. It uses **tldraw** and **Excalidraw** for the infinite drawing surface, and **@xyflow/react** for node-based workflows. Canvas state is persisted via the backend API and managed in a Zustand store (`stores/canvas.ts`).

### State management (React)

- **TanStack Query** — server-state caching, persisted to IndexedDB via `@tanstack/react-query-persist-client` + `idb`
- **Zustand** — client-side UI state (canvas, configs)
- **Context** — Auth state, configs provider (wraps API calls with current config)

### Database

SQLite database at `server/user_data/localmanus.db`, accessed via `aiosqlite` through `db_service.py`. Schema migrations are handled by `services/migrations/manager.py`.

### ComfyUI integration

ComfyUI is an optional local Stable Diffusion runtime. The Electron main process handles installation (`comfyUIInstaller.js` as a forked child process), process lifecycle (`comfyUIManager.js`), and exposes status to the renderer via IPC. The backend communicates with ComfyUI's REST API on `127.0.0.1:8188`.

### Publishing

`electron/ipcHandlers.js` uses **Playwright** with stealth plugin to automate publishing content to platforms like Xiaohongshu, Bilibili, and YouTube.

## i18n

The app supports Chinese and English via `react-i18next` + `i18next-browser-languagedetector`. Translation files are in `react/src/i18n/`.

## Python code style

Configured in `pyproject.toml`: Black (line-length 88), isort, Ruff. The server is a flat package — all routers and services import from each other directly (no `__init__.py` re-exports, though `__init__.py` files exist).
